# PRD: AI-Агент для Telegram-канала (с веб-поиском и автопостингом)

## 1. Концепция продукта

Автономный Telegram-бот, выполняющий роль контент-менеджера. Бот принимает название товара, ищет подтвержденные характеристики в интернете, генерирует экспертный пост (с защитой от галлюцинаций) и предоставляет админку для редактирования, немедленной публикации или добавления в расписание.

## 4. Ролевая модель и безопасность

Доступ к боту закрыт. Бот использует `BaseMiddleware` для фильтрации апдейтов.

- Проверка идёт по таблице `allowed_chats`
- ID чатов хранятся как `BigInteger` (для поддержки отрицательных ID супергрупп)

**Разделение интерфейсов:**

- **Личные сообщения (ЛС):** Полноценная админка с нижним меню (`ReplyKeyboardMarkup`)
- **Группы / Супергруппы:** Рабочая среда модераторов. Бот работает в тихом режиме (без нижнего меню) и общается только через `InlineKeyboardMarkup` под своими постами

## 6. Система ротации LLM-провайдеров

### Архитектура

```
LLMProvider (ABC)
├── OpenAICompatibleProvider  →  OpenAI, OpenRouter, DeepSeek
└── GeminiProvider            →  Google Gemini (google-generativeai)

ProviderRouter  →  приоритетный список провайдеров с автоматическим фолбэком
```

### Интерфейс `LLMProvider`

- `generate(messages, temperature)` → `LLMResponse(text, provider_name, model)`
- `reset()` — сброс состояния ротации
- `is_exhausted` — все варианты исчерпаны

### Логика ротации

**GeminiProvider** (модели → ключи):
1. `model[0] + key[0]` → ошибка
2. `model[1] + key[0]` → ошибка (модели кончились для key[0])
3. `model[0] + key[1]` → ошибка
4. `model[1] + key[1]` → exhausted

**OpenAICompatibleProvider** (ключи → модели):
1. `key[0] + model[0]` → ошибка
2. `key[1] + model[0]` → ошибка (ключи кончились для model[0])
3. `key[0] + model[1]` → ошибка
4. `key[1] + model[1]` → exhausted

**ProviderRouter**: при exhausted текущего провайдера → переход к следующему по приоритету. Все exhausted → `AllProvidersExhausted`.

### Конфигурация (JSON в БД)

Хранится в `settings` (ключ `llm_providers`):

```json
[
  {
    "name": "gemini",
    "type": "gemini",
    "models": ["gemini-2.0-flash", "gemini-1.5-pro"],
    "api_keys": ["AIza-key1", "AIza-key2"],
    "temperature": 0.7
  },
  {
    "name": "openrouter",
    "type": "openai_compatible",
    "base_url": "https://openrouter.ai/api/v1",
    "models": ["deepseek/deepseek-chat"],
    "api_keys": ["sk-or-key1"],
    "temperature": 0.7
  }
]
```

Порядок в массиве = приоритет. Настраивается через бота без рестарта.

## 7. Пайплайн генерации (AI-агент)

Бот использует **LangGraph** для предсказуемой генерации:

1. **Инициация:** Пользователь отправляет запрос + медиа. Бот отвечает «Собираю данные...»
2. **Сбор фактов (search_node):** Tavily ищет информацию в вебе
   - **Защита:** Если поиск падает или возвращает пустоту — жёсткий фолбэк-текст: *«❌ У меня сейчас нет доступа к веб-поиску...»*, с просьбой прислать ссылки вручную
3. **Генерация (generate_node):** `ProviderRouter` выбирает LLM по приоритету и формирует текст по `system_prompt` из БД
   - **Ротация:** При ошибке провайдера — ротация внутри провайдера (модели/ключи), затем переход к следующему провайдеру. Все исчерпаны → сообщение об ошибке
4. **Сохранение:** Пост записывается в БД со статусом `pending`

## 8. Обработка медиа и лимиты Telegram

Бот извлекает `file_id` (фото, видео, документы) из запроса и сохраняет в `media_ids`.

Перед отправкой проверяется длина `generated_text`:

- **≤ 1024 символов:** Отправляется единым сообщением (медиагруппа/файл + текст в caption)
- **> 1024 символов:** Сначала медиа без подписи, затем reply-сообщением текст (лимит 4096 символов)

## 9. Жизненный цикл поста и модерация (Inline-кнопки)

Под свежим постом (`status = pending`) доступны 5 кнопок:

| Кнопка | Действие |
|--------|----------|
| ✅ Опубликовать сейчас | Атомарно меняет статус на `published`, отправляет в канал |
| 🕒 В отложенные | Меняет статус на `approved`, пост встаёт в очередь крона |
| ✏️ Заменить текст вручную | Статус → `editing`, FSM ожидает новый текст |
| 🔄 Рерайт (AI) | Статус → `editing`, FSM ожидает промпт с правками, LLM обновляет текст |
| 🗑 Удалить | Hard Delete из БД |

## 10. Админ-панель (UI в личных сообщениях)

Навигация через `ReplyKeyboardMarkup` из 3 кнопок:

### 📝 Создать пост
Сбрасывает все FSM (`state.clear()`). Бот переходит в ожидание ввода товара.

### 🗂 Очередь постов
Выводит посты со статусом `approved`. Сообщение динамически редактируется для навигации.

- **Список:** Пагинация по 5 постов. Кнопки: `[1] [2] ... [← Назад] [Вперёд →]`
- **Просмотр:** Текст/превью поста. Кнопки: `[✅ Опубликовать] [✏️ Редактировать] [🗑 Удалить] [🔙 В список]`

### ⚙️ Настройки (Inline-подменю)

**🧠 Редактировать промпт:**
- Поддерживает «склейку» длинных текстов: бот просит прислать текст частями, кнопка `[✅ Я закончил отправку]`
- Поддерживает загрузку `.txt` файлов
- После подтверждения обновляет ключ `system_prompt` в таблице `settings`

**🕒 Настроить расписание:**
- Бот запрашивает CRON-строку
- Валидация через `CronTrigger.from_crontab(user_text)`
- При ошибке — повторный запрос. При успехе — обновление БД и `reschedule` без рестарта

**🤖 Настроить LLM-провайдеры:**
- При нажатии бот сразу отправляет текущий JSON-конфиг провайдеров (аналогично показу текущего промпта)
- Затем просит загрузить новый `.json` файл с конфигом
- Валидация структуры перед сохранением
- При ошибке валидации — сообщение об ошибке и повторный запрос файла
- Порядок провайдеров в JSON-массиве = приоритет (первый элемент — высший приоритет)
- Обновляет ключ `llm_providers` в таблице `settings` без рестарта

## 11. Планировщик задач (крон)

- **Инструмент:** APScheduler 3.x (AsyncIOScheduler), таймзона `Europe/Moscow`
- **Логика:** При срабатывании забирает самый старый пост (`ORDER BY created_at ASC LIMIT 1`) со статусом `approved`
- **Исполнение:** Публикует в канал, меняет статус на `published`
- Посты в статусе `editing` строго игнорируются
- Пустая очередь — тихий пропуск (без ошибок и уведомлений)
